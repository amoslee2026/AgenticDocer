# ADR-008：M05 降级为内部接口与检索边界划定

- **状态**：已接受（2026-09-16，依用户批注 B5/B8 及澄清）
- **决策者**：用户（批注 + 澄清「保留 M05 但降级为内部接口」）
- **影响范围**：M05、M06 端点表、M-LR、functional REQ-M05-F01/F02、ADR-005（关键词检索）

## 背景

批注 B5 与 B8 指出同一件事：

> %%lightRAG侧语义检索不在本项目范围；%%
> [!TODO] 图遍历和检索是LightRAG的业务范围，不在本项目实现；只需要给lightRAG提供接口就行

原设计中 M05（图遍历与检索）实现 `traverse`（refs 多跳 CTE）与 `search_text`（PG FTS），并在 M06 暴露 `GET /nodes/{id}/traverse` 与 `GET /search` 两个公开端点。批注要求把「检索」整体划给 LightRAG。

**但**完全删除 M05 会留下一个空洞：M-LR 的增量导出需要知晓 refs 图结构（`composes_from` 的父子聚合、`traces_to` 的上游链），否则无法构造 LightRAG 所需的「结构化上下文块」。

## 决策

**保留 M05 实现，降级为内部接口**（用户裁决）：

1. **实现保留**：`traverse()` 与 `search_text()` 继续实现与维护（含 `KIND_RULES`、跳数语义、去重/环截断规则）。
2. **端点移除**：M06 删除 `/traverse` 与 `/search`；M07 从不曾有（确认无遗漏）。
3. **消费者变更**：唯一调用方改为 **M-LR 导出**（`mlr/export.py` 内部调用），用于构造 LightRAG 导出包的图结构上下文。
4. **对外检索能力**：完全由 LightRAG 承担；本系统只提供导出接口（渲染文本 + node_id + 增量事件流）。

**边界表**：

3. **消费者变更**：主要消费方改为 **M-LR 导出**（`mlr/export.py` 内部调用），用于构造 LightRAG 导出包的图结构上下文；**次要消费方为 M09B 质量门**（关键词检索辅助），故原「唯一调用方」措辞已修正为「主要消费方 M-LR，次要 M09B」（V14）。
|---|---|---|
| 结构化点查（按 node_id/anchor/doc 取节点） | 本系统 M06 | `GET /nodes/{id}` 等 |
| 文档节点树、章节树 | 本系统 M06 | `GET /docs/{id}/nodes`、`/sections` |
| refs 图遍历（多跳） | **内部** M05，供 M-LR | 无公开端点 |
| 关键词全文检索（FTS） | **内部** M05，仅供质量门/导出辅助 | 无公开端点 |
| **语义检索**（向量/图 RAG） | **LightRAG** | 本系统仅导出数据 |
| 文档间关联推理 | **LightRAG** | 同上 |

## 后果

**正面**：
- 职责单一：本系统=确定性结构化权威源，LightRAG=语义检索；
- 删除 2 个公开端点，减少 API 面与测试面；
- M-LR 仍能获得图结构，导出包质量不降。
| refs 图遍历（多跳） | **内部** M05，供 M-LR | 无公开端点 |
| 关键词全文检索（FTS） | **内部** M05，供 M-LR 与 **M09B 质量门** | 无公开端点 |
**负面 / 代价**：
- **ADR-005（关键词检索实现）降级**：FTS 从「用户可用的检索能力」变为「内部辅助」；`nodes.text_fts` 生成列与 GIN 索引保留（M-LR 导出与质量门仍在用，且删除成本高于保留）；
- M05 无公开消费者后，其测试从「API 契约测试」改为「M-LR 集成测试」，覆盖路径变化；
- 用户若需「在本系统内搜索」需经 LightRAG（跨系统一跳）。

**风险**：LightRAG 未就绪期间（C7 摄入暂缓），**系统内无任何检索能力**（除按 ID 直读与文档树浏览）。此风险已知并接受：本阶段定位是「结构化权威源 + 导入/渲染」，检索待 LightRAG 联调。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 完全删除 M05（含实现） | M-LR 导出缺图结构，需重新实现等价逻辑，且 A19 的跳数语义/去重规则会被重写 |
| 保留 M05 公开端点 | 与批注字面冲突；检索双源（本系统 FTS + LightRAG 语义）造成口径分裂，违反 P5 |
| 改挂到 M-LR 之下作为子模块 | 等价于本决策，仅命名差异；保留 M05 编号更利于 ID 稳定（不影响既有 REQ 引用） |
