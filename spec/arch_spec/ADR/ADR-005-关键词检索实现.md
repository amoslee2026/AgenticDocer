# ADR-005: 关键词检索实现（FTS vs pg_trgm）

## Status
Accepted（2026-09-16）

## Context
M05 需在 PG 内提供关键词检索（REQ-M05-F02），语料为英文行业规范（PCIe/AMBA/CXL/JEDEC），目标 P95 <200ms（B10）。候选：`tsvector` 全文检索（english 配置）与 `pg_trgm` 模糊匹配。

## Decision
以 **tsvector（english 配置）全文检索**为主实现；`pg_trgm` 列为按需增强（ADR 复审触发条件：需要子串/拼写容错时）。索引：`nodes` 上以生成列/表达式索引 `to_tsvector('english', coalesce(content->>'text',''))` 建 GIN。

## Trade-offs
| 维度 | tsvector english（采用） | pg_trgm |
|---|---|---|
| 词干化/停用词 | 原生（英文规范文档适配） | 无（子串匹配） |
| 查询语法 | 词/短语/布尔（websearch_to_tsquery） | LIKE/相似度 |
| 中文语料 | 不适（需 zhparser——当前语料无中文） | 可兜底 |
| 索引体积 | 中 | 大 |
| 排序质量 | ts_rank 相关度 | 相似度 |

## Consequences
- Positive：英文语料开箱即用；查询语法贴近用户直觉。
- Negative：中文/子串场景弱（触发 pg_trgm 复审）。
- Risks：`content->>'text'` 依赖各原子 schema 的统一文本字段（M01 约束 `content.text` 必填用于检索）。

## Alternatives Considered
| 方案 | 优点 | 缺点 | 放弃理由 |
|---|---|---|---|
| pg_trgm only | 容错强 | 无词干化/排序弱；索引大 | 主场景是词组检索 |
| 外部检索引擎（ES 等） | 功能最强 | 新基础设施 | 违背最小栈；规模不需要 |
