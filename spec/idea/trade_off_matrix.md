# Trade-off 决策矩阵

生成：2026-09-16（it.idea 完整模式）。评分 1–5（5 最优）；权重合计 100；方案定义见 `approach_analysis.md`。

## 1. 方案级对比（A/B/C）

| 维度 | 权重 | A 自研单体 | B 渐进文件 | C 现成工具 |
|---|---|---|---|---|
| P1 格式合规（结构性保证） | 20 | 5 | 2 | 4 |
| P2/P4 精确引用与多跳 | 20 | 5 | 2 | 3 |
| P3 人机评审（批注/状态） | 15 | 5 | 2 | 4 |
| P5 异构文档建模自由度 | 15 | 5 | 4 | 2 |
| 建设成本（越高越省） | 15 | 2 | 5 | 4 |
| 长期演进自由度 | 10 | 5 | 3 | 2 |
| 工具/技术风险 | 5 | 3 | 5 | 3 |
| **加权总分** | 100 | **4.45** | **3.00** | **3.25** |

计算：A = (20×5+20×5+15×5+15×5+15×2+10×5+5×3)/100 = 4.45；B = (20×2+20×2+15×2+15×4+15×5+10×3+5×5)/100 = 3.00；C = (20×4+20×3+15×4+15×2+15×4+10×2+5×3)/100 = 3.25。**A 胜出**，且其失分项（建设成本、Q3/Q5 风险）均有局部缓解（分阶段交付、ADR 裁决）。

## 2. 关键技术决策点（供 arch_spec/ADR 继承）

| # | 决策点 | 选项 | 倾向 | 理由（量化依据） |
|---|---|---|---|---|
| D1 | 存储 | 纯 PG+JSONB（v0.1 已定） vs PG+图库 | 纯 PG | v0.1 §9 已裁决；节点量级 ≤100k（B10 v1.1），多跳 ≤2 跳可纯 SQL 递归 CTE |
| D2 | LightRAG 部署 | 同实例同库（LIGHTRAG_* 表） vs 独立实例 | 同库不同表 | Q1 已据源码核实可行（表名前缀隔离）；少一个实例的运维面 |
| D3 | 前端框架 | React+TS vs 其他 | React+TS | Agent 熟悉度 ★★★★★；v0.1 §5.1 借鉴 Sanity（React 生态） |
| D4 | 表单引擎 | RJSF vs JSON Forms vs 轻量自研 | Phase 5 ADR | 自研风险 vs 适配成本，评分待原型验证 |
| D5 | 渲染模板 | Jinja2 vs 程序化 | Phase 5 ADR | 往返保真是第一约束（B9） |
| D6 | 解析粒度（Q4） | 条款级 vs 段落级 | Phase 5/试点裁决 | 条款级与规范文档结构匹配；段落级过度切分 |
| D7 | 导入审核载体 | WebUI 审核 vs CLI 审核 | CLI 先行、WebUI 跟进 | M03 阶段（阶段 1）时 WebUI（M08）未就绪；CLI 审核即可闭环 |
| D8 | API 契约 | OpenAPI（FastAPI 原生） | 采用 | 前后端并行开发的边界（Agent 分工架构知识库） |

## 3. 已被否决的选项（记录理由，防重复讨论）

| 选项 | 否决理由 |
|---|---|
| 独立图数据库（Neo4j 等）承载引用图 | v0.1 §9 已否决；≤100k 节点纯 PG 足够；多一个基础设施面 |
| 采购商业 CCMS（DOORS/Jama/Polarion） | v0.1 §9 已否决（席位定价、部署重、无强制认证需求） |
| 全自动 PDF/markdown 直转结构化 | 违背 GigaRAG「自动解析质量不可控」原则（其 README L5）；B11 半自动 |
| 全量 URN 注册表 | 对单机单库过早（B8）；文件级 ID + 章节锚足够起步 |
| 微服务拆分 | 单机单用户（C4/B6），模块化单体（M01–M09）已满足隔离需求；拆分徒增运维 |
