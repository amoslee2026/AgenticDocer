# ADR-004: 渲染引擎与模板策略（Q5）

## Status
Accepted（2026-09-16）

## Context
M04 将节点树渲染为 Markdown：需（a）`format:html` 片段**零改写**直通（E1）；（b）frontmatter 按 C5 回写；（c）图片相对路径重写；（d）渲染唯一执行者并产出 `normalize()` 供一致性判定（P5）。候选：Jinja2 模板 vs 程序化生成。

## Decision
采用**程序化渲染**：`render/` 下按 `atom_type` 分派的纯函数管线（`render_node(node) -> str` 序列拼接），不使用 Jinja2。模板化仅保留在文档骨架（frontmatter 序列化）这一层。

## Trade-offs
| 维度 | 程序化（采用） | Jinja2 |
|---|---|---|
| HTML 直通保真 | 天然（直接拼接） | 需 `\| safe` 且易误加转义/空白控制 |
| 可测性 | 纯函数 + normalize 对比 | 模板渲染测试较绕 |
| 表达力（复杂布局） | 代码表达 | 模板更直观 |
| 学习/维护 | Python 单一技能面 | 双技能面（模板语法） |
| 变更审查 | diff 即代码 diff | 模板 diff 隐式 |

## Consequences
- Positive：零改写保证（P4）在实现层可审计；渲染函数可单测。
- Negative：布局类需求（未来 HTML/PDF）需写更多代码。
- Risks：空白/换行的精确控制全靠代码纪律 → 以 normalize 往返测试兜底（§10）。

## Alternatives Considered
| 方案 | 优点 | 缺点 | 放弃理由 |
|---|---|---|---|
| Jinja2 模板 | 布局直观；非程序员可改 | 转义/空白陷阱与直通冲突；双技能面 | P4 直通保真优先 |
| 混合（模板+直通占位符） | 折中 | 两套机制并存，链路复杂 | 复杂度不换收益 |
